Starting Jarvis from the terminal

QUICK START

The one command. Came home with the Mac? This starts everything — bridge in the background, Codex opened, status checks — and tells you when it's safe to say the magic words:

cd ~/Documents/Home_IoT && ./jarvis
./jarvis status # what's running? ./jarvis logs # follow the bridge log (hi/bye + errors) ./jarvis down # stop the server processes

First run ever (unpaired): it starts in the foreground instead so you can scan the pairing QR — then Ctrl+C and ./jarvis again.

Under the hood — the manual equivalent of what ./jarvis does:

cd ~/Documents/Home_IoT/src/jarvis_switch source .venv/bin/activate python jarvis.py

2 · Start a voice session. Normally Siri does this ("Call Jarvis"), but from the terminal — open a second terminal tab:

cd ~/Documents/Home_IoT/src/jarvis_switch source .venv/bin/activate python session.py start # audio → HomePod/iPhone, greeting, Codex voice chat python session.py end # farewell + audio restored ("Dismiss Jarvis")
Rule of thumb — where commands run: there are only two working folders. Bridge & voice session commands → ~/Documents/Home_IoT/src/jarvis_switch. Device scripts (hue.py, homewizard.py, bosch.py, matter.py, homekit.py) → ~/Documents/Home_IoT/src/devices. Every python command needs the venv active first — your prompt then shows (Jarvis). SwitchAudioSource, launchctl, echo … >> .env work from anywhere, no venv.

Before a session can open with project context: Codex must be running with its front window on a chat inside the Home_IoT project.

Handy · list all audio devices (names for AUDIO_OUTPUT / AUDIO_INPUT in config.py — details in the Audio section):

SwitchAudioSource -a -t output # all outputs (find the HomePod) SwitchAudioSource -a -t input # all inputs (find the iPhone mic) SwitchAudioSource -c -t output # which output is active right now

Audio — HomePod out, iPhone in

DO NOW

Edit src/jarvis_switch/config.py and set the two names so they match macOS exactly:

AUDIO_OUTPUT = "HomePod Living Room" # Jarvis's voice AUDIO_INPUT = "Your iPhone Microphone" # Jarvis's ears

Find the exact names (any terminal, no venv needed):

SwitchAudioSource -a -t output # HomePod's AirPlay name SwitchAudioSource -a -t input # iPhone Continuity mic name
Why the HomePod / soundbar don't appear in that list: the Sound menu mixes real audio devices with AirPlay targets (Living Room HomePod, Apple TV, Q-Series soundbar). AirPlay targets only become audio devices while selected, so SwitchAudioSource can't switch to them when idle. And macOS Shortcuts has no "Set Playback Destination" action (iOS-only — checked 2026-08-15). The working route: the session clicks the device in the menu-bar Sound flyout for you, found by name via accessibility.
  1. One-time: System Settings → Control Center → Sound → "Always Show in Menu Bar" (the script opens that icon's flyout).
  2. In config.py set AUDIO_OUTPUT_AIRPLAY = "Living Room" — the name exactly as shown in the Sound menu (or the Q-Series soundbar's name instead).
  3. Test routing alone:
    cd ~/Documents/Home_IoT/src/jarvis_switch source .venv/bin/activate python session.py airplay # Sound flyout opens, Living Room gets selected
  4. Away from home? Set AUDIO_OUTPUT_AIRPLAY = "" to fall back to plain device switching via AUDIO_OUTPUT.
  • Restoring audio on "Dismiss Jarvis" still works — your previous output is a normal device SwitchAudioSource can switch back to.
  • iPhone mic needs Continuity: nearby, same Apple ID, BT + Wi-Fi on (System Settings → General → AirDrop & Handoff).

Test the whole session without Siri:

cd ~/Documents/Home_IoT/src/jarvis_switch && source .venv/bin/activate python session.py start # greeting from the HomePod = success python session.py end # audio restored

Greeting text & voice: GREETING, FAREWELL, VOICE in the same file.

Electricity & gas — HomeWizard P1

✓ WORKING

Configured 2026-08-14. IP + token live in .env (HW_P1_IP, HW_P1_TOKEN).

Daily use:

cd ~/Documents/Home_IoT/src/devices source ../jarvis_switch/.venv/bin/activate python homewizard.py summary # power now, kWh totals, gas python homewizard.py power # watts (negative = exporting) python homewizard.py gas # gas meter reading
"Jarvis, how much power is the house using?" · "What's the gas reading?"

Full setup from scratch (redo if the meter is reset, its IP changes, or the token is deleted):

  1. HomeWizard app → Settings → Meters → your P1 → enable Local API.
  2. Find the meter's IP (same app screen, or router client list — look for "HWE-P1"). Give it a DHCP reservation in the router so it never changes.
  3. Save the IP:
    echo "HW_P1_IP=192.168.x.x" >> ~/Documents/Home_IoT/.env
  4. Pair — run this, then press the physical button on the P1 meter within 60 seconds (token saves to .env automatically):
    cd ~/Documents/Home_IoT/src/devices source ../jarvis_switch/.venv/bin/activate python homewizard.py pair
  5. Verify (same terminal): python homewizard.py summary
Needs firmware ≥ 6 for API v2 (update via the HomeWizard app) and the Mac on the same network as the meter.

Appliances — Bosch Home Connect

✓ WORKING

Configured 2026-08-14. Device-Flow app "Jarvis" at developer.home-connect.com; tokens in .env.

Daily use:

cd ~/Documents/Home_IoT/src/devices source ../jarvis_switch/.venv/bin/activate python bosch.py appliances # washer, dishwasher, dryer + state python bosch.py status <haId> # active program + remaining time
"Jarvis, is the washing machine done?" · "Anything running at home?"
About tokens (normal behavior, not a bug): the access token expires after ~24 h by design. The script now auto-refreshes it using the refresh token (~2-month lifetime), so this is usually invisible. If it still says unauthorized — refresh token expired or was revoked — redo step 4 below. One warning per ~2 months is expected.

Full setup from scratch:

  1. Developer account at developer.home-connect.com — use the same email as your Home Connect phone-app account (that link is what exposes your real appliances).
  2. Register Application: Application ID Jarvis, OAuth Flow: Device Flow (cannot be changed later), testing-account field blank (same email) — or your app-account email if different, Success Redirect blank, all three Advanced checkboxes unchecked (especially One Time Token Mode). Copy the Client ID.
  3. Save it:
    echo "BOSCH_CLIENT_ID=paste-here" >> ~/Documents/Home_IoT/.env
  4. Authorize — opens a URL; log in with your Home Connect account and approve (tokens save to .env automatically):
    cd ~/Documents/Home_IoT/src/devices source ../jarvis_switch/.venv/bin/activate python bosch.py auth
  5. Verify (same terminal): python bosch.py appliances — three machines should list.
A freshly created Client ID can take a few minutes to activate — if auth says "invalid client", wait 5 minutes and retry. Works from any network (cloud API) — no need to be home.

Aqara (M3 hub) — sensors, plugs, shades, AC

✓ WORKING

Route 1 — LOCAL via Matter (recommended, implemented, no waiting): the M3 is a Matter bridge, and Matter allows multiple controllers. A local Matter server on this Mac reads the same sensors Apple Home sees — no cloud, works offline, instant.

  1. Install the Matter server into the venv (large download, one time):
    cd ~/Documents/Home_IoT/src/devices source ../jarvis_switch/.venv/bin/activate pip install -r requirements-matter.txt
  2. Start the server — same terminal (venv still active); it keeps running, leave this tab open (or install the launchd agent, step 5, and skip this):
    matter-server --storage-path ~/Documents/Home_IoT/matter-data
  3. iPhone Home app → the M3 hub accessory → Accessory Details → Turn On Pairing Mode → note the setup code, then within ~15 min, in a new terminal tab:
    cd ~/Documents/Home_IoT/src/devices source ../jarvis_switch/.venv/bin/activate python matter.py commission 1234-567-8901 # your code
  4. Wait ~1 minute (bridge interview), then — same terminal as step 3:
    python matter.py sensors # all temp/humidity + battery python matter.py temp "Bedroom" # one sensor by name python matter.py states # doors / leaks / smoke states python matter.py on "Air Purifier" # control: plugs on/off python matter.py open "Roller Shade" # shades: open/close/position N python matter.py ac # aircon status (room temp, mode) python matter.py ac cool 22 # cool to 22 C; also: heat N, off, auto
    Matter is bidirectional — plugs and shades are controllable, sensors are readable. (Commissioned 2026-08-16: 23 endpoints came through, including the Air Conditioner at ep 2.)
  5. Give devices their room names. The M3 exposes product names ("Aqara Temp/Humidity Sensor" ×3), so edit ~/Documents/Home_IoT/src/devices/matter_aliases.py and map endpoints → your names ("Bedroom", "Air Purifier", …). The file explains how to identify which endpoint is which (compare readings with the Aqara app, breathe on a sensor, toggle a plug by on "ep 23"). Until aliased, target devices by endpoint number.
  6. Lifecycle — nothing to install: after this one-time setup, the server runs on demand: it starts automatically when a Jarvis session begins and stops on "Dismiss Jarvis" (MATTER_ON_DEMAND in config.py). The first Aqara query of a session may take a few extra seconds while it boots — matter.py waits automatically. Optional alternative for always-on use (e.g. future leak alerts): the launchd agent
    cp ~/Documents/Home_IoT/src/jarvis_switch/com.jarvis.matter.plist ~/Library/LaunchAgents/ launchctl load ~/Library/LaunchAgents/com.jarvis.matter.plist
    If launchd (or a manual server) is already running, sessions detect it and leave it untouched.
"Jarvis, what's the bedroom temperature?"
Sensor names come from the M3's bridged labels — rename sensors in the Aqara app if matter.py sensors shows unhelpful names. If pip can't resolve the CHIP wheels, try Python 3.12 for the venv.

Route 2 — Aqara cloud API (application submitted 2026-08-15, awaiting moderation): kept as backup in aqara.py. If approved and ever needed: save AppId/AppKey/KeyId + region domain in .env, then have a dev agent implement the signed calls. With Route 1 working, this is optional.

The Siri chain — pair the bridge & wake phrases

DO NOW

This connects "Hey Siri" to Python. The Mac runs a virtual HomeKit bridge (Jarvis Bridge) carrying the Jarvis trigger switch; Siri scenes flip that switch; flipping it starts/ends the voice session.

1 · Start the bridge — it prints a QR code and PIN, keep it running:

cd ~/Documents/Home_IoT/src/jarvis_switch source .venv/bin/activate python jarvis.py

2 · Pair with Apple Home (once, at home):

  1. iPhone → Home app → + → Add Accessory.
  2. Scan the QR code shown in the terminal. If the camera won't read it: More options… → Jarvis Bridge → enter the 8-digit PIN printed under the QR.
  3. Accept the "uncertified accessory" warning — normal for DIY accessories.
  4. Assign rooms; both switches arrive together: Jarvis (the trigger) and Jarvis Light (a command switch for later).

3 · Create the voice scenes — Siri activates a scene by speaking its name, and several scenes can flip the same switch, so you can have as many wake phrases as you like:

  1. Home app → + → Add Scene → Custom.
  2. Scene Call Jarvis → Add Accessories → Jarvis → tile set to On → Done.
  3. Scene Wake up, daddy's home → same accessory, also On. (Second wake phrase.)
  4. Scene Dismiss Jarvis → Jarvis set to Off. (Ends the session, restores audio.)
Phrase tips: if Siri mishears or tries to phone a contact, rename the scene — the spoken phrase is always exactly the scene name. Test each phrase once on the HomePod; adjust wording until Siri gets it reliably.

4 · Test the full chain — bridge running, Codex open on a project chat:

"Hey Siri, Call Jarvis" → terminal prints hi → HomePod greets you → voice chat opens.
"Hey Siri, Wake up daddy's home" → same thing.
"Hey Siri, Dismiss Jarvis" → farewell → audio restored.
Troubleshooting pairing: accessory not found → Mac and iPhone on the same network? Firewall allowing Python? · Want to re-pair from scratch → stop the bridge, delete src/jarvis_switch/jarvis.state, remove the bridge from the Home app, start again (the QR/PIN regenerate). · The bridge process must be running at all times for Siri to reach it — autostart via launchd is in the Improvement queue.

Apple Home devices — Eve watering & friends

NEEDS PAIRING

Devices that live only in Apple Home are driven via command switches — virtual switches Python flips, which your Home-app automations react to.

  1. Pair the Jarvis Bridge once (at home): run it, scan the QR from the Home app. Full steps: docs/setup-jarvis-switch.md.
  2. One switch per routine in src/jarvis_switch/config.py:
    COMMAND_SWITCHES = ["Jarvis Light", "Jarvis Water Garden"]
    Restart the bridge — new switches appear in Apple Home automatically.
  3. Home app → Automation → An Accessory is Controlled: two automations per switch (turns on → … and turns off → …).
  4. Use (the Jarvis Bridge must be running):
    cd ~/Documents/Home_IoT/src/devices source ../jarvis_switch/.venv/bin/activate python homekit.py list python homekit.py on "Jarvis Water Garden"
"Jarvis, water the garden" — it confirms first, by design.
